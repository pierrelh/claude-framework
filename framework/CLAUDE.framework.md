# Framework operating rules

This repository uses an AI project framework. GitHub is the source of truth for **what** to
do (issues + Project board/roadmap); this repo is the source of truth for **how** (code, docs,
agents). Owned by the upstream template — do not edit this file in a project.

## Where things are
- `.fw/config.json` — language, autonomy mode, GitHub ids, capacity, role → agent mapping.
- `.fw/state.json` — backlog keys → issue numbers (written by `fw`, don't edit by hand).
- `.fw/backlog/*.json` — backlog batches as proposed and applied.
- `.claude/agents/` — this project's agent team (generated by `/fw-team`).
- `framework/bin/fw` — CLI for every GitHub Project operation. **Use it instead of hand-written
  `gh project` / GraphQL calls.** `framework/bin/fw -h` lists commands.
- `framework/standards/` — the rules for stories, estimates, agents, docs, git.
- `docs/` — human documentation (Obsidian vault / MkDocs site).

## Commands
| Command | Purpose |
|---|---|
| `/fw-init` | One-time setup, new project or adoption of an existing one |
| `/fw-doctor` | Check the machine and GitHub access, guide the fixes |
| `/fw-brief` | Write or revise the product brief |
| `/fw-team` | Design or revise the agent team |
| `/fw-backlog <request>` | Turn a need (initial or new) into qualified GitHub issues |
| `/fw-plan` | Discuss estimates and capacity, compute the roadmap |
| `/fw-work [#issue\|all]` | Implement stories through the agent team, PR, review, merge |
| `/fw-status` | Where the project stands |
| `/fw-retro [milestone]` | Retrospective: estimates vs actuals, recurring review findings → improvements |
| `/fw-docs` | Bring docs and `CLAUDE.md` back in sync with the code |
| `/fw-update` | Pull the latest framework version from the template |

## Rules for every session
1. Talk to the user in `language` from `.fw/config.json`; write issues in `issue_language`
   and docs in `docs_language`. Prompts, code, commits and identifiers stay in English.
2. Work goes through the backlog: non-trivial requests become issues first (`/fw-backlog`),
   then are implemented with `/fw-work`. Trivial fixes may skip the backlog but still go
   through a branch and a PR.
3. Respect `autonomy`: `assisted` → ask before merging and before starting each story;
   `auto` → chain stories and merge on green review/QA/CI, but still stop on the escalation
   conditions of `/fw-work`.
4. Delegate to the project's agents for their roles (`roles` in config). If an agent is not
   loaded in this session, run a general-purpose subagent with the agent file as its prompt.
5. Keep docs true: any change to commands, conventions, architecture or behaviour updates
   `CLAUDE.md` / `docs/` in the same PR.
6. Never edit `framework/`, `.claude/skills/fw-*` or `docs/framework/` in a project — they
   are replaced by `/fw-update`.
