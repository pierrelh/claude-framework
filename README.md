# Claude Framework — an AI project framework for Claude Code

Repository: <https://github.com/pierrelh/claude-framework>

A project template where an **AI agent team** runs day-to-day project management and
delivery with you: from a need (precise or deliberately vague) to qualified GitHub issues,
a Kanban board and a roadmap, then to reviewed, tested, documented pull requests.

> After `/fw-init`, this README is replaced by your project's README. The framework
> documentation lives in [docs/framework/](docs/framework/README.md).

## What you get
- **`/fw-init`** — guided setup: environment and GitHub checks (with fix instructions),
  language, autonomy mode, repository + GitHub Project (Kanban + Roadmap) on your account,
  product brief, stack, a custom **agent team** for your stack, a backlog of **qualified,
  measured, estimated user stories**, the roadmap and the docs.
- **Daily loop** — `/fw-work` implements stories through the team (spec → code + tests →
  review → QA → docs → PR → merge) and keeps the board and roadmap truthful;
  `/fw-backlog` turns new needs into issues; `/fw-status` tells you where you are.
- **Two autonomy modes** — assisted (you approve) or fully automatic (agents merge
  themselves, with guard rails).
- **Living docs** — `CLAUDE.md` for agents, `docs/` for humans: an Obsidian vault that is
  also a MkDocs site.
- **Existing projects** — the framework can be installed into an existing repository;
  `/fw-init` then maps the codebase first.

## Requirements
[Claude Code](https://docs.claude.com/en/docs/claude-code), git, Python ≥ 3.8,
[GitHub CLI](https://cli.github.com/) ≥ 2.40 logged in with the `repo`, `project` and
`workflow` scopes. `/fw-init` checks everything and explains the fixes.

## Start a new project
```bash
# Option A (recommended) — https://github.com/pierrelh/claude-framework → "Use this template"
#   → create your repository, then clone it:
gh repo create my-project --template pierrelh/claude-framework --private --clone && cd my-project
# Option B — clone the template directly (/fw-init offers a fresh git history)
git clone https://github.com/pierrelh/claude-framework.git my-project && cd my-project
claude
> /fw-init I want to build …
```

## Attach an existing project
```bash
git clone https://github.com/pierrelh/claude-framework.git ~/claude-framework   # once
python3 ~/claude-framework/framework/bin/fw.py install /path/to/existing-project
cd /path/to/existing-project && claude
> /fw-init
```
`fw install` copies the framework files, merges `.claude/settings.json`, prepends the
framework import to an existing `CLAUDE.md` and never overwrites your files.

## Commands
| Command | Purpose |
|---|---|
| `/fw-init` | One-time setup (new or existing project) |
| `/fw-status` | Progress, projected dates, what needs you |
| `/fw-work [#n\|all\|N]` | Deliver stories through the agent team |
| `/fw-backlog <need>` | New feature or bug → qualified GitHub issues |
| `/fw-plan` | Capacity, estimates, roadmap |
| `/fw-team` | Design or revise the agent team |
| `/fw-brief` | Write or revise the product brief |
| `/fw-docs` | Re-sync docs with the code, optional GitHub Pages |
| `/fw-doctor` | Machine and GitHub access check |
| `/fw-update` | Pull the latest framework version |

## Repository layout
```
CLAUDE.md                 agent memory: imports framework rules + project section
.claude/settings.json     hooks (session context, guard) and safe permissions
.claude/skills/fw-*/      the /fw-* commands
.claude/agents/           the project's agent team (generated by /fw-team)
.fw/config.json           language, autonomy, GitHub ids, capacity, roles
framework/bin/fw          CLI: doctor, github-setup, backlog, schedule, next, done…
framework/hooks/          session context + safety guard
framework/standards/      user stories, estimation, agents, docs, git
framework/templates/      brief, agent, ADR, backlog example, docs workflow
framework/tests/          unittest suite for fw.py and the hooks (stdlib only)
docs/                     human docs (Obsidian vault / MkDocs site)
```

## Maintaining the template
- Run the tests before every change: `python3 -m unittest discover -s framework/tests`
  (stdlib only, no network — GitHub calls are mocked, install/update run on throwaway git repos).
  CI runs them on every pull request (`.github/workflows/framework-tests.yml`, template-only:
  not copied into projects). A new `fw` command or guard rule comes with its tests.
- Bump `framework/VERSION` on each change to framework-owned files (`framework/MANIFEST`).
- Optional: set `framework.template_project` in `.fw/config.json` to a GitHub project
  (`owner/number`) that already has Kanban and Roadmap views — new projects are then copied
  from it, views included.
